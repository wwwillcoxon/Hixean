Hixean es un compilador a C11 sin dependencias: se compila con un gcc o un clang y a partir de ahí compila programas a binarios nativos. Un PRINT "Hola mundo" ocupa 8 896 bytes. Esta página es la guía de instalación completa; el resto de documentos están en el directorio.

Lo que trae, sin adornos

Cada ejemplo de esta página se ejecuta con hxc y su salida es la de verdad. Si algún día dejan de cuadrar, la CI lo dice.

Result<T,E> y ? propagan el error como valor. No hay excepciones ni setjmp: el runtime no tiene tabla de personalidades.

Los registros tienen subtipado structural de anchura: un Perro sirve donde se pide un Animal, y el compilador materializa la copia. Los ENUM nunca participan: son nominales.

Una función genérica se compila una vez por cada combinación de tipos que aparece. Sin tabla de despacho, sin boxing: el C generado es el mismo que si se hubiera escrito a mano.

Rango(a, b) es [a, b). Los iteradores son perezosos: TAKE sobre mil elementos consume tres.

ARENA reserva de verdad (mmap en freestanding, malloc en libc) y DEFER ejecuta al salir del bloque, en orden inverso. Los dos comparten mecanismo: un flag de modo y epílogos encadenados, sin pila en el runtime.

Un paquete es un manifiesto .hxk con lo que da, lo que necesita y con qué perfil se construye. hxc query pregunta qué hay en las rutas sin compilar nada.

Puertas, no promesas

El tamaño del ejecutable no es una curiosidad: es una puerta que la CI comprueba en cada cambio. Si sube de 12 KiB, falla la compilación.

  • 8 896 Bhola mundo, perfil freestanding
  • 12 288 Bla puerta
  • 60 msfront-end + emisión a C, 10 012 líneas
  • 9 ms20 módulos sin cambios (caché de objetos)

Sin unwinding

Los errores son valores. La propagación con ? se traduce a una etiqueta y un return; si nadie la acepta, el programa sale con el código 70. No hay tabla de personalidades en el binario.

Capacidades, no permisos

ENABLE net en el fuente dice qué usa el programa; CAPABILITY net en el manifiesto dice qué se autoriza. Si no coinciden, hxc build --kit se niega a construir.

Verificado donde se puede

1 / 0 es E0305 en el verificador y una trampa en ejecución. La suite manda un datagrama por loopback y lo recibe: los sockets son syscalls directas, sin libc.

Sin dependencias

El front-end es C11 estándar. Se compila con make, se prueba con make test y no descarga nada. No hay paso de compilación previa ni biblioteca que instalar.

Veintiún hitos, de M0 a M20

No fue una lista de features: cada hito cerró una puerta que estaba abierta.

  1. M0–M4léxico, MATCH, Result, DEFER, ARENA
  2. M5–M8genéricos, traits, iteradores, ENUM, lambdas, división verificada
  3. M9PTR, compilación paralela, paquetes .hxk
  4. M10subtipado structural con materialización
  5. M11capacidades y std.net con sockets reales
  6. M12consultas .hxq
  7. M130.1.0: -Werror, sanitizers, fuzzer, check --json, extensión de VS Code
  8. M14distribución: releases con checksum, Homebrew, winget, registro de paquetes
  9. M15a.Len() y a.At(i) con la comprobación puesta
  10. M16OPERATOR: el programa define + para su propio TYPE
  11. M17MAYBE T y NIL, sin operadores nuevos
  12. M18UNIQUE: el campo REF es el dueño del préstamo
  13. M19ARRAY[T]: el arreglo que crece con Push y avisa con At
  14. M20-I, HX_LIB y std.texto, que se encuentra sola

Instalarlo

Cuatro caminos. El primero es el que funciona siempre y es el que se usa para trabajar; los otros dos son para quien ya tiene el binario y quiere que se lo busque el sistema.

Qué hace falta antes

  • Un compilador de C11: gcc o clang. Nada más. En Linux hace falta make; en Windows, el clang de LLVM o Build Tools de Visual Studio.
  • Nada de lo que suelen pedir los lenguajes: no hay python de por medio para compilar, ni node, ni gestor de paquetes. El Makefile llama a cc y ya.
  • Para las seis plataformas de la release, git: la instalación por red usa la API de GitHub.

1 · Desde el código, que es el camino serio

git clone https://github.com/wwwillcoxon/Hixean
cd Hixean
make
make test

make test compila el corpus entero y compara su salida con la esperada. Si pone 0 fallos, el compilador funciona en esta máquina. make size comprueba lo otro: que hola mundo sigue entrando en 12 KiB.

2 · Desde la release, que es el camino corto

curl -fsSL https://raw.githubusercontent.com/wwwillcoxon/Hixean/main/tools/install.sh | sh
hxc version

El instalador descarga el tarball de la última release para tu plataforma, comprueba el SHA256 contra SHA256SUMS y aborta si no coincide. Sin ese SHA256 no instala nada. Para instalar una versión concreta: sh tools/install.sh 0.2.0. Y para instalar sin red, un tarball local: sh tools/install.sh ./hixean-0.2.0-linux-x64.tar.gz.

Ojo: la release 0.2.0 publica un solo artefacto, el de linux-x64. En macOS y Windows este comando no encuentra su plataforma: compilar el código funciona en los dos, pero para tener un binario hay que usar el camino del sistema. Las otras plataformas entran en la release cuando su puerta de CI esté verde.

3 · Homebrew

brew install --formula=packaging/homebrew/hixean.rb

La fórmula está en el repositorio, con el sha256 sin rellenar: funciona cuando la release exista. Publicarla en un tap es un paso pendiente, no una instrucción que hoy funcione.

4 · winget

# aún no está en winget-pkgs
winget show wwwillcoxon.Hixean

El manifiesto está en packaging/winget/ y falta enviarlo a microsoft/winget-pkgs. Cuando esté, winget install wwwillcoxon.Hixean.

Comprobar que ha ido bien

Un hxc version que no responde, o un programa que no compila, casi siempre son la misma cosa: el hxc que se está ejecutando no es el que crees. Estos tres pasos lo aclaran.

hxc version
printf 'PRINT "Va"
' > v.hxe
hxc run v.hxe
hxc check v.hxe

hxc run compila y ejecuta. hxc check solo comprueba y no genera nada, y es la mitad de rápido: para un programa que no va a ejecutar todavía, es la forma de trabajar.

El primer programa

Un archivo .hxe es un programa ejecutable. El punto de entrada no se declara: es el archivo. No hay main, ni using, ni punto y coma obligatorio.

En qué sistemas funciona

El compilador se compila en los seis sistemas que publica la release: Linux, macOS y Windows, en x64 y arm64. Compilarlo no cuesta nada: es C11 sin dependencias.

Los programas que genera son otra cosa, y conviene decirlo claro: con el perfil freestanding, que es el que trae su propio _start y habla con el kernel directamente, el binario que sale es de Linux x86-64. En macOS y Windows el perfil por defecto es libc, y ahí los programas sí se ejecutan. Por eso la puerta de los 12 KiB se mide solo en Linux.

No es una manera de esconderlo: está en la gramática, en el manual y en la guía, en el mismo sitio donde se explica qué perfil hace cada cosa.

Qué está verificado, y dónde

La CI corre en Linux, macOS y Windows. Lo que está verde ahora mismo:

  • Linux: las siete puertas. Es donde se mide el perfil freestanding y donde corre el perfil de red con sockets reales.
  • macOS y Windows: el compilador se construye y el corpus pasa 33 de 34. La que falla es tests/genericos.hxt, y solo en la interpolación de un entero dentro de una función genérica: donde Linux imprime 777, macOS imprime tres bytes que no son 7. La prueba que sale verde es la que importa; esta está en rojo y a la vista.

El fallo aún no está explicado. El código que genera el compilador es el mismo en los dos sistemas, así que la causa está en el runtime o en el enlazado de macOS, y hace falta una máquina con macOS para mirarlo. Mientras tanto, la release no se publica para esas plataformas.

Dónde queda instalado, y cómo se quita

prefijo/
  bin/hxc          el compilador
  lib/hixean/      la biblioteca estándar (std.texto)

El compilador mira su propia biblioteca en <hxc>/lib y en <hxc>/../lib/hixean, así que no hay variables de entorno que configurar. Para quitarlo: borrar el prefijo. No deja nada más, porque no hay registro central ni configuración en tu carpeta personal.

Cuando algo falla

  • «no se encontró cc»: falta el compilador de C, o no está en el PATH. En Debian y Ubuntu, build-essential.
  • Un error de módulo: hxc busca primero en el directorio del archivo, luego en -I, luego en HX_LIB. Para mirar en otra parte: hxc build p.hxe -I ../bibliotecas.
  • Un diagnóstico que no entiendes: cada código E0xxx tiene su fila en la tabla del manual, con lo que significa y qué hacer. hxc check --json da lo mismo en JSON para herramientas.
  • Un programa que se para: la aritmética entera de + y - comprueba el desbordamiento y sale con el código 70. No es un fallo del compilador: es el lenguaje diciendo que el número no cabía.

Lo que todavía no existe

Está en la lista porque un manual que omite los límites se lee como un manual de un lenguaje que sí los tiene.

  • audio y gpu no existen: sin dispositivo ni compilador por objetivo con el que probarlas.
  • Sin async, sin concurrencia, sin red más allá de 127.0.0.1.
  • El compilador se compila en C, no en Hixean.
  • Sin firma de paquetes y sin índice central de registro.
